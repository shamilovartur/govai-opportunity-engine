## Реальный источник № 261

Использована сохранённая в предыдущей итерации HTML-копия приказа Росимущества
от 11.09.2020 № 261 **в редакции от 30.05.2023**:
[текст и карта источников](../examples/rosimushchestvo_261/README.md),
[оригинальная карточка КонсультантПлюс](https://www.consultant.ru/document/cons_doc_LAW_362388/).
Это не первоначальная редакция 2020 года и не оригинальный PDF.
SHA-256 файла: `8d9445aca3666c6605c4c38a5baef54a2d8c042462447f7f6fe14c0d5727b6d4`.

Проверено без LLM: 113 889 символов, 1 360 исходных фрагментов распределены
по 27 основным блокам; нет пропусков и повторного включения символов в основные
блоки. Контекст соседей может повторяться намеренно. В одном блоке контекст
ограничен; исходный текст этого контекста всё равно покрыт основными блоками.
Страницы HTML/TXT остаются неизвестными.

Ручной тестовый набор кандидатов содержит семь процедур и 14 выбранных действий.
Это **mock-контракт конвейера**, не результат обнаружения моделью и не исчерпывающая
экспертная разметка всех действий. После валидации и объединения сохранены 7/7
процедур, 14/14 действий и точные доказательства; отклонений в этом наборе нет.

## Автоматические и интерфейсные проверки

На Python 3.12.14 выполнено **155 тестов**, все прошли, включая 114 прежних.
Команды: `python -m pytest -q`, `python -m pip check`,
`python -m compileall -q app.py govai scripts tests`.
Зависимости установлены из `requirements-dev.txt`, конфликтов нет.

- **OpenAI SDK, offline transport:** реальная сериализация Responses-запроса,
  строгая JSON Schema, обязательные поля, nullable-исполнитель, `store=False`,
  отключённое усечение. HTTP 400/401/403/404/429/500, таймаут, отсутствие соединения,
  отказ модели, незавершённый ответ и некорректный/пустой JSON. `httpx.MockTransport`
  не отправляет запросы в Интернет.
- **Доказательства:** ложный ID, цитата отсутствует, цитата в существующем, но не
  переданном фрагменте, выдуманный исполнитель/результат, пустое доказательство,
  одни номера вместо подтверждения действия. Отклонения не трактуются как
  доказательство отсутствия процессов. Проверены цитаты через границу срезов.
- **Большой документ:** синтетический текст больше приказа № 261, 219 разделов,
  проверка полного покрытия, порядка и обработки каждого блока; отдельные тесты
  длинного одиночного фрагмента, соседнего контекста и родительского пункта.
  Лимит блоков проверяется до первого запроса API, ничего молча не отбрасывается.
- **Объединение:** повтор одного действия на границе блоков удаляется; разные
  действия одной процедуры, включая действия с одинаковым названием в разных
  местах, сохраняются. Связи и дополнительные поля имеют собственные цитаты.
- **Другой НПА:** реальный [отрывок частей 2 и 3 статьи 8 закона № 59-ФЗ](../tests/fixtures/law_59_article8_excerpt.md),
  редакция 28.12.2024. Тот же алгоритм сохраняет доказательство регистрации обращения.
  Ответ модели заменён mock; проверка не относится ко всему закону и не доказывает
  переносимость семантического качества настоящей модели.
- **Без процессов / неизвестная структура:** mock возвращает пустой список и
  объяснение для текста определений; ненумерованное действие сохраняет `null`
  вместо выдуманного пункта. Кириллический PDF сохраняет физическую страницу.
- **Streamlit AppTest:** кнопка, иерархия и раскрываемые доказательства, экспорт,
  отсутствие ключа, ошибки API, удаление устаревшего результата, отсутствие
  повторного анализа при обычном рендере. Положительный LLM-сценарий использует mock.
- **Chromium/Playwright, настоящее приложение:** загрузка PDF/DOCX/TXT, кнопка,
  приказ № 261 редакции 2023 года, понятное сообщение без ключа, отсутствие
  фиктивного JSON процессов и сохранение экспорта исходной структуры.

## Что ещё нужно проверить настоящими запросами

В среде с защищённым ключом, настроенной моделью и разрешённой сетью:

```bash
python -m scripts.extract_processes examples/rosimushchestvo_261/source.txt \
  --output work/261.processes.json --check-261
python -m scripts.extract_processes tests/fixtures/law_59_article8_excerpt.txt \
  --output work/59.processes.json
```

Нужно вручную сверить семь процедур раздела III и все их действия, альтернативы,
исполнителей, условия и результаты с исходными пунктами; отдельно оценить ложные
срабатывания на определениях и перечнях. Совпадение семи якорей само по себе
недостаточно. Повторить на полном другом НПА, тексте без процессов и длинном акте.
Фиксировать выбранную модель, результат JSON, пропуски и необоснованные выводы.

## Ограничения и риски

1. Точная цитата доказывает расположение текста, но не следование вывода из текста.
   Все действия помечены `requires_review`. Семантическая проверка остаётся за человеком.
2. Структура исходного документа эвристическая. Неверно распознанные пункты и
   заголовки влияют на группировку; source ID и точные смещения сохраняются.
3. Полное покрытие блоками не гарантирует полноты ответа модели. Ограниченный
   контекст может потерять дальние связи; нет глобального семантического прохода
   по всему акту. Слияние детерминированное и консервативное: перефразированные
   дубли или разделение одной процедуры по разным якорям могут остаться.
4. Размер измеряется в символах/фрагментах, а не токенах выбранной модели.
   При переполнении контекста или вывода выдаётся ошибка; уменьшение блоков
   увеличивает число запросов, время и стоимость. Прогресс есть, возобновление
   с сохранённого блока и потоковое отображение частичного результата пока отсутствуют.
5. Полнота HTML и качество извлечения PDF/DOCX отдельно не гарантируются;
   OCR и автоматическое восстановление нумерации не добавлены.
6. Текст передаётся внешнему API только по кнопке/явному CLI-запуску.
   Ключ не включается в экспорт или сообщения об ошибках. Инструкции из НПА
   объявлены недоверенными, но защита от смысловых манипуляций модели не доказана.

Изменения подготовлены к проверке в PR #1. Слияние в `main` не выполнялось.
