# Возобновление анализа больших документов

2026-11-14, ветка `codex/streamlit-document-upload`, PR #1.

Добавлен слой `govai.checkpoints` перед прежним конвейером извлечения процессов.
Алгоритмы разбиения, проверки цитат, объединения процедур и удаления дублей
сохранены. OpenAI-адаптер дополнительно объявляет версию и хеш своих инструкций.

## Сохранение и восстановление

Корректный ответ каждого блока сохраняется в исходной структуре `Candidates`.
Ошибка API, неполный/невалидный ответ или пустой ответ без объяснения не помечают
блок обработанным. При сбое `AnalysisInterrupted` содержит checkpoint и числа
успешно обработанных/всех блоков; завершённый результат не возвращается.

Идентификатор анализа SHA-256 учитывает:

- хеш исходного файла/полученного тела URL, извлечённого текста и структуры;
- провайдера, модель, версию и хеш промпта, хеш JSON Schema ответа;
- все поля `ChunkSettings` и хеш payload каждого блока с его контекстом.

Перед повторным запуском проверяется весь checkpoint, включая схему сохранённых
ответов и ID блоков. Несовместимость вызывает отказ до первого API-запроса.
Пустой checkpoint допустим; в частичном могут отсутствовать любые блоки.
После получения всех ответов прежний конвейер заново проверяет каждую цитату
и выполняет объединение. Сохранённые ложные цитаты по-прежнему отклоняются.
`execution` итогового JSON показывает ID анализа, повторно использованные блоки
и новые запросы по блокам. Это не счётчик внутренних HTTP-повторов SDK.

В Streamlit актуальный снимок сохраняется после каждого ответа в состоянии сессии.
JSON генерируется по нажатию кнопки скачивания, без создания отдельной большой
загружаемой копии после каждого блока. Скачивание не прерывает анализ и не вызывает
повторных запросов. После потери сессии пользователь заново загружает исходный НПА
и скачанный JSON, затем явно запускает продолжение. Импорт не вызывает API.
Старый совместимый снимок объединяется с текущим без потери более новых блоков;
конфликтующие ответы не перезаписываются.

CLI также возобновляет анализ из файла: по умолчанию рядом с `--output` создаётся
файл с суффиксом `.checkpoint.json`, либо используется `--checkpoint PATH`.
Запись через временный файл, `fsync` и атомарную замену сохраняет предыдущий
корректный JSON при ошибке записи. Исходный документ, checkpoint и итоговый JSON
должны иметь разные пути. При сбое итоговый файл не создаётся/не обновляется.

## Проверено

**191 автоматический тест прошёл** на Python 3.12.14, включая прежние 155.
`pip check` не обнаружил конфликтов; `compileall` прошёл.

- Сбой на третьем из четырёх блоков: сохранены ответы первых двух, сообщается 2/4.
- Возобновление запрашивает только третий и четвёртый блоки; полный checkpoint
  позволяет повторно собрать результат вообще без запросов модели.
- Восстановление после сериализации JSON и удаления исходного состояния даёт
  тот же результат объединения, что и непрерывный запуск.
- Изменение документа, текста, структуры, провайдера, модели, версии/текста промпта,
  схемы ответа, настроек блоков или payload запрещает повторное использование.
- Повреждённый/слишком большой JSON, повторяющиеся JSON-ключи, неизвестный ID блока,
  лишнее поле `api_key`, неполный или необъяснённый ответ отклоняются.
- Изменённая цитата в восстановленном ответе отклоняется прежней проверкой источников.
- Старый импорт не удаляет более новые ответы; конфликт не перезаписывает текущие данные.
- Ошибка сохранения останавливает последующие запросы; атомарная запись CLI
  оставляет предыдущий checkpoint целым.
- Streamlit AppTest: ошибка с числом блоков, доступный checkpoint без итогового JSON,
  восстановление в совершенно новой сессии, завершение, повторный запуск без API,
  отказ от несовместимого импорта.
- Chromium/Playwright: реальное скачивание checkpoint после ошибки, загрузка
  исходного НПА и JSON в новой сессии браузера, продолжение только недостающих блоков,
  скачивание итогового JSON и полного checkpoint.

Дополнительно выполнен прогон на сохранённом тексте приказа № 261 редакции
30.05.2023: 113 889 символов, 27 блоков. После mock-сбоя на блоке 20 сохранены
19 ответов; восстановление из сериализованного JSON потребовало только 8 новых
вызовов блоков и завершило все 27. Этот прогон проверяет покрытие/восстановление,
не семантическое извлечение процессов.

Провайдер в этих тестах заменён mock. В браузерном стенде журнал вызовов блоков:
`chunk-1, chunk-2 (ошибка), chunk-2, chunk-3`; повторного вызова первого блока нет.
Настоящий OpenAI API в этой итерации не вызывался. Эти тесты подтверждают управление
прогрессом и восстановлением, а не качество семантического извлечения моделью.

## Практические ограничения

- Без скачанного JSON потеря сессии Streamlit Cloud может потерять прогресс.
  Снимок содержит только ответы на момент скачивания; текущий незавершённый запрос
  в него не входит. Временный диск Cloud не используется как единственная копия.
- Если ответ API потерян до сохранения, при возобновлении этот блок придётся запросить
  снова. Checkpoint не обеспечивает гарантию однократного списания средств API.
- Файл содержит текстовые доказательства. API-ключ, заголовки авторизации, ошибки
  транспорта и объект клиента не сериализуются. Лимит импорта/экспорта — 64 МБ.
- Checkpoint не подписан. Совместимость и совпадение цитат не доказывают подлинность
  сохранённого ответа или его смысловую корректность; действия требуют проверки.
- Исходный НПА необходимо загрузить отдельно. Изменение текста/структуры парсером,
  версии промпта или тела HTML по URL корректно блокирует использование старого снимка.

Изменения подготовлены в PR #1; слияние в `main` не выполнялось.
