# AI-возможности: надёжность, перспективность и эффект

Ночная итерация 15 ноября 2026. Ветка `codex/streamlit-document-upload`, PR #1;
базовый коммит `89ec10f`. Аналитика помогает выбрать направления для проверки,
а не доказывает окупаемость, фактическую IT-архитектуру или право ИИ принимать решения.

## Пользовательский путь и границы реализации

**Загрузить НПА → «Извлечь процессы» → «Сформировать отчёт» → скачать результат.**
Извлечение и нормализация выполняются последовательно существующими функциями.
Импорт сохранённых этапов и диагностика остаются в закрытых «Технических данных».
Дополнительных обязательных действий, запросов на отдельные инициативы и аналитических
этапов нет. Транспорт OpenAI, извлечение, нормализация и checkpoint не переписаны.

| Модуль | Ответственность |
| --- | --- |
| `govai/opportunities.py` | Компактный вход, Structured Outputs, проверка источников, локальное отклонение инициатив, границы измерения и совместимость |
| `govai/economics.py` | Чистые расчёты `Decimal`, неизвестные значения, единицы, происхождение предпосылок и пересечения |
| `govai/opportunity_report.py` | Качественная рубрика, управленческое содержание, Markdown и представление эффекта |
| `govai/opportunity_ui.py` | Основной результат, готовые байты загрузок, защита от повторного запуска, восстановление |
| `govai/report_export.py` | Только оформление существующего отчёта в DOCX и сборка ZIP; без аналитики и LLM |

Новых зависимостей, хранилищ и сервисов нет. Для DOCX используется установленный
`python-docx`, для ZIP — стандартный `zipfile`. Версии текущего этапа: схема `2.1`,
промпт `opportunities-2.1`, расчёт `effect-2.1`, рубрика `prospect-1.1`. Ключ включает
документ, нормализованную карту, модель, провайдера, промпт/схему, рубрику,
настройки и индивидуальные сценарии. Старый отчёт не считается результатом новой
логики: повторяется только формирование отчёта. Сохранённые исходный анализ,
карта и checkpoint остаются совместимыми.

## Ошибка одной инициативы и целостность результата

Сначала проверяется документ и нормализованная карта существующими импортерами.
Несоответствие документа, повреждение карты или повтор ID инициативы прекращают
сборку: достоверные границы данных неизвестны. Некорректные диагностические связи
между инициативами не принимаются и сопровождаются предупреждением; они не отменяют
проверенные источники других предложений и не разрешают суммирование эффектов.

Если нарушение локализовано в одной инициативе — например, неизвестное действие,
чужое доказательство или исходный ID измерения — **эта инициатива отклоняется** с
причиной. Она не попадает в принятые предложения и не получает эффект. Другие
подтверждённые инициативы сохраняются. Отклонённые записи остаются в JSON и кратком
разделе отчёта; ложная ссылка не становится допустимой из-за статуса «гипотеза».

Некорректная необязательная оценка времени имеет другое последствие. Два сценария,
одинаковые предпосылки, неправильная единица, пустые объяснения, неподходящее
происхождение числа или нулевое время обязательной проверки могут оставить
содержательную инициативу **без числового прогноза**, с причиной и планом измерения.
Числа не заменяются выдуманными значениями. `TimeParameter` позволяет сохранить
структурно корректный ответ до строгой локальной проверки через финансовый `Parameter`.
Внешние параметры также не отменяют требования к единицам, границам измерения и
работе человека. Неопределённая добавочная ценность остаётся гипотезой с недостаточными
основаниями и без чисел; детерминированные и повторяющие предусмотренную автоматизацию
сценарии по-прежнему отклоняются. Это не ослабляет проверку источников и не обещает восстановить ответ, который вообще
не прошёл первичную структурную проверку.

`canonical_plan` по-прежнему определяет служебную модель и необходимые параметры
детерминированно по метрике. Пустой или частичный допустимый список от LLM не обрывает
отчёт. Восстановление полного JSON повторно собирает результат и сравнивает его с
сохранённым: изменённые источники, эффект или перспективность не принимаются.

## Сохранённый план и защита от повторных расходов

При быстром повторном нажатии Streamlit может сменить исполняемый скрипт. Готовый
результат сохраняется до выхода из индикатора ожидания; короткое обновление статуса
через штатный fragment только перерисовывает экран и не создаёт провайдер или запрос.

`on_plan` сохраняет структурированный план в текущей сессии **до локальной сборки**.
После её ошибки доступны локальный повтор без API и резервная копия
`opportunities-plan.json`. У копии отдельный `kind=govai_opportunity_plan`;
она не является готовым `opportunities.json` и не выдаётся за отчёт.
Экспорт и повторный импорт проверяют документ, карту, схему, настройки и ссылки.
План с нарушениями целостности не экспортируется как валидированная копия.

В техническом разделе можно восстановить такую копию, затем выполнить
**«Повторить сборку без API»**. Это перенос существующего конверта плана, не новая
система checkpoint. Повторная сборка заново применяет ограничения и проверяет
источники. Полученный результат, ожидающий план и признак активного запуска
привязаны к совместимости; повторный клик не отправляет второй запрос. Если отчёт
уже есть, показывается он. Просмотр, скачивание, открытие разделов и восстановление
не вызывают LLM. Автоматических платных повторов нет.

## Чей труд измеряется

Участник определяется по сохранившимся исходным исполнителям и проверенным ссылкам
классификации нормализованной карты. По словам в названии он не угадывается.

- Рабочее время ведомства и рабочее время МФЦ/другой организации обозначаются отдельно.
- Время заявителя допустимо измерять как **время заявителя**, но не как зарплатные
  расходы или высвобождение сотрудников ведомства.
- Неизвестный, смешанный или системный исполнитель не становится человеком ведомства.
  До уточнения участника числовая оценка труда блокируется; гипотеза сохраняется.
- Для смешанной инициативы можно явно выделить подтверждённый участок и исходные
  кандидаты одного участника. Оценка этого участка не переносится на всю инициативу.
- Уже предусмотренная автоматизация не даёт новой экономии. Дополнительная
  интеллектуальная помощь требует отдельного механизма и измерения человеческой работы.

Единая `economic_restrictions` сохраняет консервативный денежный допуск. Замечания
группировки сами по себе не делают содержательную инициативу неперспективной, но
не превращаются в доказательство реальных трудозатрат. `portfolio_assessment`
выявляет общие действия, исходные кандидаты, предков и альтернативы. Эффекты не
суммируются автоматически даже при заявлении модели о дополнении; разные единицы
не складываются в одно число. Цитата НПА подтверждает операцию, не пользу ИИ.

## Четыре метрики и индивидуальные сценарии

Выбирается одна основная метрика и при необходимости одна дополнительная для
проверки. Происхождение чисел: документ, пользователь, сценарное допущение или
неизвестно. Неизвестное не заменяется нулём; отрицательный эффект сохраняется.

| Метрика | Что считается и что нужно |
| --- | --- |
| Трудозатраты | Минуты на подходящий случай; часы на явно заданную выборку. Работа после включает проверку и исправление ИИ. Зарплата и годовая нагрузка не нужны. |
| Деньги | Годовой эквивалент мощности, расходы, внедрение и первый год раздельно; нужны собственные параметры нагрузки, использования, времени, стоимости и затрат. |
| Длительность | Время прохождения подтверждённого участка до минус после; не рабочие минуты и не ускорение всей услуги по умолчанию. |
| Качество | Метод расчёта показателя, экспертный эталон, критерий успеха и недопустимые ошибки; без наблюдений — план оценки, не процент улучшения. |

Для сценарных минут модель должна описать работу, документы/единицу случая, границы,
действия модели и оставшуюся проверку человека. Объяснения работы до и после должны
различаться; три сценария — различаться предпосылками и причиной остаточных затрат.
Одного заполненного `note` недостаточно. Простые программные проверки выявляют
пустые, повторные и внутренне противоречивые объяснения, но **не доказывают
реалистичность чисел или смысловое качество LLM**. Все предложенные моделью минуты
остаются допущениями до замеров. Модель не придумывает годовой объём, зарплаты,
стоимость разработки или наблюдения качества.

```text
Минуты на подходящий случай = Минуты до − Минуты после
Минуты на любое обращение = Минуты на подходящий случай × Доля применимости
Часы на заданную выборку = Число случаев × Минуты на случай / 60
```

Для `eligible_cases` доля применимости повторно запрещена. Для `all_cases` она
обязательна: неизвестная доля оставляет общий эффект неизвестным, хотя изменение
минут на подходящий случай может быть рассчитано отдельно.

Python также показывает **условную единицу сравнения на 1 000 случаев**. Это не
годовая нагрузка и не подстановка в неизвестный `case_count`. `standardized_hours`
содержит собственную маркировку `illustrative` и базу eligible/all; основной
`released_hours` без явно заданного числа случаев остаётся неизвестным. Для всех
обращений условный эквивалент также требует известной применимости. Формула
использует тот же рассчитанный показатель минут, без повторного коэффициента.

Контрольное новое учебное допущение: чтение и сверка одного вида комплекта занимает
20 минут до, а после, с проверкой специалистом, — 16/12/10 минут в трёх сценариях.
Различие объясняется объёмом ручных исправлений. На условных 1 000 подходящих случаев
получаются 66,67 / **133,33** / 166,67 человеко-часа. Эти числа не характеризуют
Росимущество. Если применимость среди всех обращений — явно заданные 25%, базовый
эквивалент на 1 000 всех обращений составляет 33,33 часа; без этой доли он неизвестен.

Денежная формула сохранена:

```text
Использованные случаи = Годовой объём × Применимость × Доля использования
Часы = Использованные случаи × (Минуты до − Минуты после) / 60 × Реализация эффекта
Эквивалент мощности = Часы × Полная стоимость часа
OPEX = Постоянные расходы + Использованные случаи × Расходы на случай
Чистый эквивалент первого года = Эквивалент мощности − OPEX − Внедрение
```

Эквивалент мощности не является доказанным сокращением бюджета; `budget_savings`
остаётся `null`. Неизвестные расходы не равны нулю. `illustrative_scenarios()` —
учебный набор калькулятора, не универсальная подстановка инициативам.

Пример пилота качества: числитель — существенные расхождения, пропущенные при
сверке; знаменатель — все существенные расхождения экспертного эталона.
Два эксперта согласуют разметку обезличенных завершённых дел; обычная проверка и
помощь ИИ сравниваются вслепую. Критерий — отсутствие новых пропусков существенных
расхождений и неподтверждённых юридических выводов. Это условие допуска, не прогноз
процента улучшения. Исправление технической ошибки не должно подменяться пересмотром
решения; возможен и ответ об отсутствии ошибки.

## Перспективность и управленческий отчёт

Баллов, весов, вероятностей и мест внутри категории нет. Рубрика остаётся короткой:

| Категория | Основание |
| --- | --- |
| Высокая | Конкретная добавочная польза ИИ, ограниченный измеримый пилот и контролируемые риски |
| Средняя | Полезный механизм; существенное предварительное условие ещё не выполнено |
| Низкая | Польза относительно сложности/рисков слаба либо пилот не обоснован |
| Недостаточно оснований | Нельзя оценить механизм или допустимый способ его проверки |

К заполненным значениям `value_case` и `pilot_feasibility` добавлена проверка
согласованности объяснений: пользы ИИ и альтернативы, границ, метода/критерия,
человеческого контроля и рисков. Незаполненные или противоречивые основания не
сохраняют высокую категорию. Для качества требуется `quality_protocol`: способ
расчёта, экспертный эталон, недопустимые ошибки. Содержательная гипотеза при этом
не исчезает. Это структурный контроль достаточности объяснения, не экспертный
движок и не подтверждение истинности. Неизвестные данные не означают автоматически
низкую перспективность; квот категорий нет.

Резюме называет конкретных кандидатов для первой проверки, только когда для них
есть основания. Сравнение показывает пользу, категорию с причиной, метрику и
главное условие. Краткие business cases раскрывают проблему, GenAI и обычную
альтернативу, пилот и критерий. Ограничения переводятся по фрагментам на деловой
язык, сохраняя остальной смысл фразы; внутренние ID и диагностика остаются в JSON.
Приложение содержит связанные пункты и короткие цитаты; полные доказательства —
в структурированном результате. [Учебный пример](opportunity-example.md) — ручной
mock-план на небольших реальных фрагментах, не оригинальный ответ модели.

## Экспорт и пределы сохранения

Основные действия: **«Скачать отчёт (DOCX)»** и **«Скачать все результаты (ZIP)»**.
Архив содержит DOCX, Markdown, полный `opportunities.json` и короткий текстовый
файл с реквизитами и предварительным статусом. Содержание берётся из одного
готового результата; DOCX не создаёт второй аналитический конвейер. Отдельные
Markdown/JSON доступны в техническом разделе. При ошибке подготовки DOCX они
остаются доступными для сохранения исходного результата.

Кнопки получают заранее подготовленные байты, а не отложенный callback с устаревшим
ID сессии. Скачивание и повторная подготовка файлов не вызывают модель.
**Сессия Streamlit и media-файлы не являются постоянным хранилищем.** Если пользователь
ничего не скачал, после потери сессии или процесса восстановление не гарантируется.
Текущий безопасный путь — сразу сохранить ZIP, а НПА/анализ/карту хранить отдельно.
Для гарантированного восстановления понадобится отдельно согласованное приватное
постоянное хранилище с контролем доступа и сроком удаления. Оно здесь не создавалось.

## Реальные материалы, размеры и проверки

Baseline: **366 passed за 12,41 с**. P0 завершён после **380 passed**, P1 — после
**399 passed**; окончательный прогон: **422 passed за 15,66 с**. Итоговые `pip check`,
`compileall`, `git diff --check`, браузерные загрузки и визуальная проверка DOCX
фиксируются после завершения P2: **Chromium 390/1440 px: DOCX/ZIP, JSON и резервный план восстановлены в новых сессиях без дополнительных запросов; LibreOffice: 10 страниц без пустых страниц и выхода текста за границы. Нативный мобильный Word недоступен**.

Настоящие анализ и карта проверены с `examples/rosimushchestvo_261/source.txt`
редакции 30.05.2023: **247 кандидатов, 216 записей, 30 групп, `incomplete`**.
Хеши совпадают; исходные файлы не изменены, этапы не повторялись. Подлинный Markdown
и частичная реконструкция девяти инициатив использованы как справочный материал.
Реконструкция с `kind=govai_reconstructed_reference_not_application_artifact` и
`recovery_status=partial` не передавалась в штатное восстановление; её схема не
подменялась. Потерянный оригинальный план не восстановлен.

В новом явно ручном наборе девяти инициатив получены одна высокая, шесть средних
и две оценки с недостатком оснований. Это не квота и не старые баллы: новые поля
составлены для проверки программы. Числовой трудовой сценарий допустим только для
явно ограниченного участка проверки содержания комплектов с подтверждённым
исполнителем ведомства. Три других трудовых сценария заблокированы из-за неизвестных
или смешанных участников; их гипотезы сохранены. Восемь прежних отклонений сохранены.
Полные пользовательские файлы и частный тестовый набор в GitHub не публикуются.

Размеры на этой карте: payload **370 604 байта**, полный вход с промптом/схемой
**393 848 байта** при лимите **400 000**. Запас небольшой; больший документ может
быть отклонён **до платного запроса** с понятной причиной. Данные не усекаются:
повторяющиеся цитаты и поля передаются по ссылкам. Максимум — 800 записей, ответ
20 000 токенов, таймаут 300 секунд, без автоматического повтора. Тестовый план девяти
инициатив с тремя сценариями имеет **56 641 символ / 93 755 UTF-8 байт**. Это не
точная оценка токенов и не доказательство, что реальный ответ уложится в лимит.
Обрезанный ответ не считается успешным.

Минимальный GitHub Actions workflow использует Python 3.12, `requirements-dev.txt`,
`pytest` и `compileall`; без ключей, внешних API и реальных LLM-вызовов. Все проверки
генерации здесь используют контролируемые mock-ответы: **реальных OpenAI-вызовов — 0**.
Качество нового промпта настоящей моделью ещё не подтверждено.

## Один настоящий запуск в Streamlit Cloud

1. Загрузить тот же НПА; в **«Технических данных»** импортировать `processes.json`
   и восстановить `normalized_processes.json`. Это не повторяет извлечение и нормализацию.
2. Закрыть технический раздел и нажать **«Сформировать отчёт»**. Используются прежние
   `OPENAI_MODEL` и защищённый секрет; новый отчёт — один существующий этап.
3. Проверить основания первых пилотов, участников, границы работы, сценарные
   объяснения и альтернативные исходы. Не ожидать обязательных девяти инициатив
   или заданного числа высоких категорий.
4. Сразу скачать **ZIP** и при необходимости отдельный DOCX. Для новой сессии
   восстановить те же входные этапы и `opportunities.json` из архива — без API.
   При ошибке локальной сборки скачать резервный план и выполнить локальный повтор.

Частичная реконструкция не заменяет ни полноценный отчёт, ни резервный план.
Не нужно менять её `kind`/схему ради импорта.
