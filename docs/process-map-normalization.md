# Карта процессов: реализация и проверка

2026-11-14. Ветка `codex/streamlit-document-upload`, PR #1. Слияние с main не выполнялось.

## Исходные данные и граница подтверждённого результата

Приложенный пользователем фактический `processes.json` доступен и проверен целиком:
38 групп, 247 уникальных действий, 27/27 обработанных блоков, 1 отклонённый кандидат
(`quote_not_in_sent_fragment`). Исходный файл — 1 298 650 байт. Его хеши, реквизиты,
все основные и дополнительные цитаты и координаты совпали с
[`source.txt`](../examples/rosimushchestvo_261/source.txt) приказа Росимущества
от 11.09.2020 № 261 **в редакции от 30.05.2023**.
SHA-256 источника: `8d9445aca3666c6605c4c38a5baef54a2d8c042462447f7f6fe14c0d5727b6d4`.

В нормализованном представлении входа: 720 уникальных записей доказательств,
215 исходных фрагментов. Текст каждого фрагмента передаётся один раз, доказательства
ссылаются на его диапазоны; полный вход вместе с инструкцией и схемой — 325 766 байт.
Ничего из исходного анализа не усечено. Подробные поля и все доказательства остаются
в программно собранном результате, модель возвращает только план.

**В этой итерации настоящих вызовов LLM: 0.** Ключа API в среде нет, новый полный
запуск извлечения не делался. Качество смысловой нормализации настоящей моделью,
её время и расход токенов ещё не измерены. Исходный файл указывает `gpt-6.1-sol`
и 27 запрошенных блоков, но не содержит времени и токенов. Сообщённые пользователем
«около 20 минут» не превращены в измеренную метрику приложения.

Полный пользовательский JSON и браузерные выгрузки в репозиторий не добавлены.
Для регрессий сохранены только 15 релевантных кандидатов с исходными ID; длинные
цитаты в фикстуре не дублируются, а восстанавливаются из публичного текста НПА.

## Что изменилось

- `govai/analysis_io.py`: проверка завершённого результата, уникальности ID,
  соответствия документу и каждого доказательства; сохранение исходных байтов.
  Полям `validation`/`requires_review` доверие не предоставляется.
- `govai/normalization.py`: независимый от UI и провайдера этап, строгая схема
  плана, общий справочник доказательств, лимиты запроса, проверка ссылок и связей,
  консервативные запреты слияния, полный учёт кандидатов, сборка/восстановление
  артефакта и Markdown. Собственные версия промпта и версия схемы.
- `govai/llm.py`: общий транспорт Structured Outputs используется существующим
  извлечением и новым адаптером нормализации. Модель берётся из прежней настройки,
  секрет не входит в результат. Для второго этапа один запрос, без SDK-повторов,
  таймаут 300 секунд; сохраняются фактическое время, число запросов и API usage,
  включая доступные метрики неудачной попытки.
- `govai/map_ui.py`: один renderer для нового/импортированного результата;
  компактная карта, выбор категории/страницы/процесса/действия, условный вывод деталей
  и цитат только выбранного действия, восстановление и три экспорта.
- `govai/document_ui.py`, `app.py`, `govai/process_ui.py`: краткие реквизиты,
  отдельные технические данные, явный импорт `processes.json`. Бизнес-логика
  нормализации в UI не размещается; исходный результат доступен при сбое второго этапа.
- README, тесты UI и новые тесты импорта/нормализации/SDK/старого checkpoint.

`govai/processes.py`, `govai/checkpoints.py`, алгоритмы PDF/DOCX/TXT/URL,
промпт первого этапа и его версия **не изменены**. Зависимости не добавлены.

названием и составные кандидаты с общей цитатой также проверены отрицательными тестами.

## Учёт кандидатов и спорные решения

У каждого нормализованного узла есть `source_action_ids`; у каждого исходного
кандидата — запись `accounting` со всеми его назначениями и категорией. Непокрытые
ID автоматически сохраняются как отдельные review-узлы. Неизвестные ID, циклы,
чужие доказательства и повреждение карты не принимаются как корректный результат.

Объединение требует объяснения; разные явно указанные исполнители, несовместимые
каналы/сроки/условия, разные положительные и отрицательные исходы или сомнение
блокируют слияние. Ошибочное объединение исправления с ответом об отсутствии
ошибки отдельно проверено и отклоняется. Разделение составного кандидата
требует явной причины и подтверждений. Родительское обобщение не считается
независимой операцией. Исходные условия, зависимости, альтернативы и отклонения
не перезаписываются краткими названиями модели.

В тестах каждый кандидат учтён; в браузерном плане для полного файла учтены
**247/247**, неучтённых ID — **0**. Это проверка механизма учёта с фикстурой.
Число спорных объединений настоящей LLM-карты пока неизвестно: такая карта здесь
не генерировалась. Тесты намеренно сомнительных и неполных планов дают статус
`incomplete`, отдельные review-узлы и конкретные причины; не выдают их за полный анализ.

- Полный набор после изменений: **238 тестов прошли** (7,16 с). `pip check` — без конфликтов;

  недостающие блоки.
- Импорт: чужой документ, ложные цитаты/координаты/пункты, дубли ID, поддельные
  validation-флаги, другой формат JSON, повторяющиеся JSON-ключи и NaN отклоняются.
- Нормализация: смысловые дубли из реального файла, разные исполнители/каналы/условия,
  сроки и альтернативы, обобщения/дочерние операции, контекст заявителя, отрицание
  автоматизации, одинаковые названия, разделение составного кандидата, неизвестные
  ссылки, пропущенные ID, изменённая карта и несовместимые ключи.
- Другой реальный источник: отрывок ст. 8 закона № 59-ФЗ с mock-кандидатом регистрации;
  тот же алгоритм сохраняет срок и не придумывает способ выполнения/исполнителя.
  Документ без кандидатов получает пустую карту с объяснением без API-запроса.
- OpenAI SDK с HTTP mock: строгая схема, отдельный промпт, отсутствие повторов,
  usage, 403, 429, отказ, обрезанный ответ и невалидный JSON. Ошибка второго этапа
  сохраняет оригинал; отсутствие ключа не предлагает повторить извлечение.
- Streamlit AppTest: импорт без извлечения, один вызов нормализации, выбранные детали,
  отсутствие повторов при навигации, восстановление в новой сессии без ключа,
  экспорт с `on_click='ignore'`.

Браузерный сценарий Chromium/Playwright прошёл на **1440×1100** и **390×844**:
полный файл, пагинация и выбор процесса/действия, раскрытие деталей и цитат,
скачивание трёх форматов, побайтовое совпадение исходного JSON, восстановление
карты в новой мобильной сессии. Горизонтального переполнения страницы нет;
широкие таблицы прокручиваются внутри своего контейнера, выбранные названия и
цитаты переносятся по ширине экрана. Снимки экрана просмотрены.

В успешном полном сценарии был **1 mock-вызов нормализации**, 0 вызовов извлечения,
**0 дополнительных вызовов при навигации, скачивании и восстановлении**. Все
247 исходных ID учтены. Нормализатор заменён явной тестовой фикстурой; это не
проверка качества настоящей LLM. Production-приложение отдельно прошло импорт
полного файла, показ понятной ошибки второго этапа при отсутствии ключа и
выгрузку исходного JSON без изменения байтов. Настоящих API-вызовов — 0.

## Использование готового результата без повторного извлечения

1. В опубликованном приложении загрузить тот же НПА, для данного JSON — сохранённый
   `examples/rosimushchestvo_261/source.txt` редакции 30.05.2023.
2. «Импортировать готовый исходный анализ» → свой `processes.json` →
   «Импортировать результат». Импорт обозначается явно и не вызывает модель.
3. «Построить карту процессов» — выполнить **только реальный второй этап** с уже
   настроенными секретом и моделью. Именно этот запуск ещё нужно оценить в Cloud:
   самостоятельность процедур 3.2–3.8, процессы других разделов, качество слияния,
   альтернативы, категории участников и ручной разбор review-узлов. Число процессов
   не фиксируется, качество первого этапа повторно не доказывается.
4. Сохранить исходный JSON, нормализованный JSON и Markdown. При новом открытии
   загрузить тот же НПА и `processes.json`, затем «Восстановить готовую карту без API»
   → `normalized_processes.json` → «Восстановить карту». Повторная генерация не нужна.

## Ограничения и риски

- Проверка точной цитаты подтверждает расположение, но не смысл пересказа, правильность
  категории или эквивалентность действий. Все узлы сохраняют `requires_review: true`.
  Консервативные запреты могут отложить обоснованные слияния; это безопаснее потери деталей.
- Успешная сборка означает полноту учёта исходных кандидатов, а не полноту процессов
  НПА. Ошибки и пропуски первого этапа сохраняются как предмет содержательной проверки.
- Сейчас один глобальный проход: максимум 400 кандидатов / 400 000 байт входа /
  32 000 токенов ответа. Приложенный файл помещается. Вход сверх лимитов отклоняется
  до API, а не скрыто обрезается. Многозапросное разбиение нормализации не реализовано.
  Оценка объёма ответа приблизительная; обрезанный ответ отклоняется целиком.
- При сетевой ошибке после отправки возможна оплата провайдеру без полученного
  артефакта. Автоматических повторов нет; новая попытка второго этапа явная.
- Сохранение в сессии не является долговременным. Требуются скачанные файлы и исходный
  НПА. JSON не подписан: проверки не удостоверяют подлинность метрик или автора плана.
- Импорт строго сравнивает файл, текст и реквизиты. Другой формат того же акта,
  изменённая HTML-страница или изменённая структура парсера могут оказаться несовместимы.
- Не реализованы AI-инициативы, экономика, приоритизация, новые хранилища или очередь.
