# GovAI Opportunity Engine

GovAI помогает найти возможности для применения ИИ в нормативном акте:
загрузить документ → **«Извлечь процессы»** → **«Сформировать отчёт»** → **«Скачать отчёт PDF»**.
В результате — первые кандидаты для пилота, ожидаемая польза, условия проверки
и ссылки на положения документа. Рекомендации предварительные: приложение не
подтверждает фактические трудозатраты и не принимает юридические решения.

Основной интерфейс на русском: файл или HTTPS-ссылка, краткий перечень процессов,
отчёт и скачивание. Извлечение и нормализация выполняются последовательно внутри
второго шага. Импорт, подробная карта и диагностика доступны в закрытых
**«Технических данных»**. Пользователю не нужно выбирать модель или вводить API-ключ:
защищённые настройки задаёт владелец размещения. Чтение документа, восстановление
сохранённых результатов, просмотр и скачивание не вызывают OpenAI API.

## Возможности и ограничения

- **PDF:** текст всех страниц по порядку. Нужен текстовый слой; OCR сканов
  пока нет. Для PDF с паролем приложение предлагает загрузить копию без защиты.
- **DOCX:** абзацы и таблицы основного тела документа по порядку, включая
  вложенные таблицы. Колонтитулы, текстовые поля и текст на изображениях не извлекаются.
- **TXT:** UTF-8 (включая BOM) по умолчанию; UTF-16 с BOM и Windows-1251
  можно выбрать в закрытых «Дополнительных настройках TXT» после выбора файла.
  Автоматического угадывания кодировки нет.
- **URL:** прямой PDF или основной текст HTML через Trafilatura. Явные заголовки
  и номера передаются в тот же `govai.structure.structure_document`, что и файлы.
- Один файл размером до **10 МБ**. Пустые, повреждённые и неподдерживаемые
  документы вызывают понятное сообщение в интерфейсе.
- Результат — обычный текст; исходное оформление и сложная вёрстка не сохраняются.
  В многоколоночных PDF порядок текста может отличаться от визуального.
- Дополнительно сохраняются явные маркеры пунктов и подпунктов, разделы,
  реквизиты с текстовыми доказательствами и физические страницы PDF.
  Неопределённые значения остаются `null`; структура требует проверки.

Документ обрабатывается в памяти процесса Streamlit и не сохраняется приложением
на диск. При локальном запуске обработка происходит на вашем компьютере;
при размещении на сервере файл передаётся этому серверу. Внешние сервисы
для извлечения текста не вызываются. При нажатии **«Извлечь процессы»** фрагменты
документа передаются в OpenAI API. Затем та же кнопка последовательно запускает
нормализацию: проверенные кандидаты и справочник доказательств отправляются в настроенную модель;
**«Сформировать отчёт»** передаёт компактную карту операций и нужные доказательства
для предложений AI-инициатив. Все три генерации могут тарифицироваться. Статистика
использования Streamlit отключена.

## Установка и запуск

Рекомендуется **Python 3.12**. Все команды выполняйте из корня репозитория.

```bash
git clone https://github.com/shamilovartur/govai-opportunity-engine.git
cd govai-opportunity-engine
# До слияния PR переключитесь на ветку с приложением:
git switch codex/streamlit-document-upload
python -m venv .venv
```

Активируйте окружение:

```bash
# Linux / macOS
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Установите зависимости и запустите приложение:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте **http://localhost:8501**, выберите документ и дождитесь появления
реквизитов документа. Полный текст находится в **«Технических данных»**.
Для TXT при необходимости раскройте «Дополнительные настройки TXT» и измените кодировку.
Чтобы обработать другой документ, замените файл в поле загрузки.
Остановка сервера: `Ctrl+C` в терминале.

## Загрузка по ссылке

Переключите «Способ загрузки» в **«Загрузить по ссылке»**, вставьте публичный
HTTPS-адрес и нажмите одноимённую кнопку. После получения документа доступны
тот же просмотр текста/структуры и скачивание JSON. Новый запрос удаляет прошлый
результат до загрузки; ошибка не подменяется ранее полученным документом.
Обычный повторный рендер интерфейса и скачивание JSON не вызывают повторный запрос.

Программный вызов:

```python
from govai.url_input import extract_url_document

document = extract_url_document("https://example.org/document.pdf")  # замените адрес
```

В `source` добавляются `type` (`file`, `url_pdf`, `url_html`), исходный
`original_url`, конечный `final_url`, время получения `retrieved_at` в ISO 8601
с UTC и `text_sha256`. У URL-результатов `sha256` относится к полученному телу
ответа после распаковки gzip, а `completeness: "unverified"` не позволяет
считать HTTP 200 доказательством полноты. У локальных файлов URL и время
сетевого получения отсутствуют.

HTML не получает выдуманных страниц: `page_number` и `page_number_basis`
остаются `null`. Trafilatura удаляет оформление и содержимое вне основного
текста. Смещения относятся к **извлечённому тексту**, а не HTML-коду. Автоматические
номера `<ol>`/CSS не достраиваются; явные текстовые номера сохраняются по возможности.

Загрузчик отказывает при 401/403, частичном HTTP-ответе 206/Content-Range,
несовпадении Content-Length, обрыве ответа, незавершённом PDF, странице входа,
заметных признаках подписки/продолжения, оглавлении или слишком коротком тексте
(менее 200 символов после HTML-извлечения). Это консервативные проверки:
короткий полный акт или страница со ссылкой «Открыть полный текст» тоже могут
быть отклонены. Произвольное смысловое усечение автоматически обнаружить
невозможно; для каждого HTML-результата интерфейс просит сверить полноту.
JavaScript, авторизация, обход ограничений и обход связанных страниц не выполняются.

### Сетевые ограничения и защита

- Только HTTPS и порт 443; логин/пароль в URL, localhost, внутренние домены,
  непубличные IPv4/IPv6, нестандартная запись IP и IPv6 transition-адреса запрещены.
- A/AAAA проверяются перед **каждым** переходом. Наличие хотя бы одного
  непубличного адреса или ошибка проверки DNS приводит к отказу.
- Подключение закреплено за проверенным IP; повторного разрешения исходного
  имени при соединении нет. TLS SNI и HTTP Host сохраняют исходное имя,
  сертификат проверяется для него. Это предотвращает замену назначения через DNS rebinding.
- Не более трёх перенаправлений; каждый адрес проверяется заново. Циклы и переход
  с HTTPS на HTTP отклоняются. Автоматические redirects/retries отключены.
- Максимум 10 МБ как полученных, так и распакованных данных; размер проверяется
  и по заголовку, и при чтении. Поддержаны identity/gzip, другое сжатие отклоняется.
- Таймауты подключения/чтения — 5 секунд; DNS — до 5 секунд на запрос A/AAAA.
  Общий бюджет 30 секунд контролируется между сетевыми операциями; это не
  отдельный жёсткий таймер для разбора HTML или каждого байта HTTP-заголовков.
- Cookies и netrc-авторизация не используются. Настроенный администратором
  HTTPS-прокси и CA (`HTTPS_PROXY`, `NO_PROXY`, `REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE`)
  учитываются; даже CONNECT через прокси направлен на проверенный IP.
  Прокси должен поддерживать такой CONNECT и соблюдать его назначение.

Если в окружении запрещён DNS или прокси допускает только доменные CONNECT,
загрузчик покажет ограничение и предложит загрузить файл. Он не отключает проверки
ради обхода политики сети. Успешная внешняя URL-загрузка в текущем окружении
**не подтверждена**. Регрессии PDF/HTML и 403 используют настоящие локальные
TLS-соединения, напрямую и через тестовый CONNECT-прокси; они не доказывают
доступность конкретного внешнего источника.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pip check
python -m pytest -q
```

Тесты создают документы в памяти: проверяют PDF с несколькими страницами,
DOCX с таблицей, кодировки TXT, лимит размера, повреждённые и пустые файлы,
PDF с паролем и без текста. Проверки интерфейса через Streamlit AppTest
покрывают стартовый экран, успешное извлечение во всех форматах и сообщения
об ошибках. Для файлов в AppTest подменяется только загрузчик, извлечение настоящее.
URL-тесты используют контролируемые HTTP-ответы с настоящими PDF/HTML-парсерами.
Проверяются 403, частичные ответы, авторизация, редиректы, DNS, лимиты размера,
gzip, таймауты, IP/TLS-настройки и отсутствие старого результата после ошибки.
В интерфейсных URL-тестах загрузка заменена подготовленным результатом.

Baseline текущей итерации — **448 passed**. Регрессии проверяют существующий
конвейер, короткое представление нового ответа модели, совместимость старых
артефактов, защиту от повторного запроса и доступность исправных экспортов при
ошибке одного формата. Успешный mock-тест не подтверждает качество настоящего LLM.
Итоги полного прогона и ограничения опубликованной проверки фиксируются в PR.

Для независимой проверки подготовлены публичные тексты: фрагмент статьи 8
59-ФЗ, фрагмент статей 20–22 152-ФЗ и текст изменения МРОТ 429-ФЗ от 28.11.2025.
На этом этапе проверены локальное чтение и структура; для 59-ФЗ — также TXT,
DOCX, PDF и кодировка Windows-1251. Это **не реальные новые проходы LLM-конвейера**.
Сценарий с 429-ФЗ предназначен для проверки допустимого результата без подходящих
AI-инициатив. Происхождение и границы материалов описаны в
[методике](docs/ai-opportunities.md#независимые-контрольные-документы).

Для ручной проверки загрузите последовательно TXT, DOCX и PDF с известным
текстом, сравните результат с оригиналом, затем загрузите повреждённый PDF
и удалите выбранный файл. Старый результат должен исчезнуть.

Проверка запущенного сервера из другого терминала:

```bash
curl --fail http://localhost:8501/_stcore/health
```

Ожидаемый ответ: `ok`.

## Формат структурированного результата

`govai.extraction.extract_document(filename, data, encoding=...)` возвращает
обычный словарь, совместимый с JSON. Прежний `extract_text(...) -> str` сохранён.

| Поле | Значение |
| --- | --- |
| `source` | Тип источника, имя, формат, хеши; для URL — исходный/конечный адрес и время получения |
| `text` | Неизменённый результат извлечения; без нормализации пробелов и удаления повторов |
| `pages` | Диапазоны страниц; PDF: физический индекс от 1, DOCX/TXT/HTML: `number: null` |
| `metadata` | Тип, название, номер, дата принятия, дата редакции; каждое значение имеет исходный текст и диапазон-доказательство |
| `sections` | Разделы, заголовки Word и предполагаемые заголовки; `kind` отличает явные признаки от гипотез |
| `clauses` | Только наблюдаемые номера, уникальный ID, родитель (если найден), раздел, список ID фрагментов |
| `fragments` | Текст, точные смещения, строка извлечённого текста, страница, пункт и способ определения принадлежности |
| `warnings` | Машиночитаемые ограничения и неопределённости |

Все `start`/`end` — индексы **символов Python**, от нуля, конец не включён:
`fragment['text'] == result['text'][start:end]`. Это не байтовые смещения,
не координаты PDF и не индексы UTF-16 JavaScript. Конкатенация **всех** фрагментов
восстанавливает `text` полностью, включая пробелы и разделители страниц.

Для будущей ссылки на AI-сценарий сохраняйте `source.sha256`, `source.text_sha256`,
`clause.id` и `fragment.id`. Отображаемого номера недостаточно: номера могут
повторяться в приложениях. Членство в пункте определяет `fragment_ids`, а не весь
интервал `clause.start:end`: внутри интервала могут быть редакционные примечания,
которые сохранены отдельно. Дочерние пункты также имеют собственные фрагменты.

Даты нормализуются в ISO только из явно указанной корректной даты. Дата изменения
другим приказом не считается автоматически датой редакции всего документа.
Номера и реквизиты не берутся из имени файла и не достраиваются по пропускам.

## Извлечение административных процессов

1. Настройте `OPENAI_API_KEY` в менеджере секретов среды размещения или в локальном
   `.streamlit/secrets.toml` (файл исключён из Git). Имя настройки в TOML —
   `OPENAI_API_KEY`. Не добавляйте ключ в код, README, shell-историю или репозиторий.
   Приложение также читает ключ из переменной окружения, если секрет внедряется средой.
2. Задайте модель через переменную окружения **`OPENAI_MODEL`**. Например, в Linux:
   `export OPENAI_MODEL=gpt-4.1-mini`; в PowerShell:
   `$env:OPENAI_MODEL="gpt-4.1-mini"`. Выберите доступную вашему проекту модель
   с поддержкой Responses API и Structured Outputs. Модель по умолчанию не подставляется.
3. Разрешите HTTPS-доступ к `api.openai.com:443` в среде размещения. Системные
   прокси и доверенные сертификаты сохраняются; проверка TLS не отключается.
4. Запустите приложение, загрузите документ файлом или ссылкой и нажмите
   **«Извлечь процессы»**. Извлечение и нормализация выполняются последовательно;
   после них на странице появится краткий перечень процессов. Нажмите
   **«Сформировать отчёт»**, затем **«Скачать отчёт PDF»** или
   **«Скачать все материалы ZIP»**. Подробная карта,
   доказательства и исходный JSON доступны в закрытом разделе **«Технические данные»**.

Текст в поле просмотра не редактирует исходный документ для анализа. Кнопка отправляет
его структурированные фрагменты в API; обычный рендер и скачивание результат повторно
не запрашивают. При смене документа или неудачной новой попытке старый результат удаляется.
Без ключа, модели, при отказе, лимите API, таймауте, обрезанном или неверном JSON выводится
ошибка. Демонстрационных результатов и автоматической подмены провайдера нет.
Ошибка любого блока не позволяет выдать частичный результат за завершённый анализ.

### Продолжение после ошибки и checkpoint

После каждого корректного структурированного ответа сохраняется checkpoint.
При ошибке показано число обработанных блоков. Нажмите **«Продолжить анализ»**
ещё раз: сохранённые блоки не отправляются в API повторно, обрабатываются только
недостающие. После завершения все ответы проходят прежние проверку цитат и объединение.
В рамках сессии ответы разных анализов хранятся отдельно, по идентификатору анализа.

**«Скачать checkpoint JSON»** в **«Технических данных»** сохраняет последний доступный снимок, в том числе
во время работы или после ошибки. Скачивание не запускает анализ заново. Для
продолжения после перезагрузки страницы:

1. Загрузите тот же исходный НПА и настройте ту же `OPENAI_MODEL`.
2. Откройте **«Технические данные»**, выберите скачанный файл в поле **«Checkpoint JSON»**
   и нажмите **«Восстановить checkpoint»**.
3. Нажмите **«Извлечь процессы»** (или **«Продолжить анализ»** после ошибки)
   для обработки недостающих блоков, итоговой проверки и нормализации.

Сравниваются хеш исходного документа, хеш извлечённого текста и структуры,
провайдер/модель, версия и хеш промпта, схема ответа, все параметры разбиения
и хеши входных данных блоков. Несовместимый файл отклоняется до запросов API.
Импорт старого совместимого снимка не удаляет более новые ответы; конфликтующие
ответы одного блока не перезаписываются. Максимальный размер checkpoint — 64 МБ;
ограничение исходных PDF/DOCX/TXT остаётся 10 МБ.

Checkpoint содержит промежуточные ответы модели и цитаты, **не завершённый анализ**.
API-ключ и состояние SDK в него не входят. Файл не подписан и не доказывает
подлинность вызова модели; цитаты из восстановленных ответов проверяются заново.

Долговременная копия в Streamlit Cloud — **скачанный вами JSON**, а не временный
диск сервера. Без скачивания потеря сессии может потерять прогресс; ответы после
момента последнего скачивания в этот снимок не попадут. Для URL изменение тела
страницы, даже при похожем тексте акта, делает старый checkpoint несовместимым.
Исходный документ в checkpoint не упакован — сохраните его отдельно.

CLI автоматически сохраняет checkpoint рядом с итоговым файлом и использует
его при повторении той же команды. Путь можно задать явно:

```bash
python -m scripts.extract_processes examples/rosimushchestvo_261/source.txt \
  --output work/261.processes.json --checkpoint work/261.checkpoint.json --check-261
```

Файл checkpoint заменяется атомарно после каждого ответа; итоговый JSON пишется
только после завершения. При смене параметров используйте новый путь checkpoint.
Проверки восстановления описаны в [docs/checkpoint-recovery.md](docs/checkpoint-recovery.md).

### Как устроен анализ

- `govai.llm.OpenAIProvider` вызывает Responses API со строгой JSON Schema,
  `store=False`, отключённым автоматическим усечением и лимитом вывода 12 000 токенов.
  Таймаут запроса 90 секунд, не более одного повтора SDK при временных ошибках.
  `store=False` не означает отсутствие всех служебных журналов у провайдера:
  обращайтесь к правилам хранения данных вашего API-проекта.
- `govai.processes` зависит только от протокола `ProcessProvider.extract(payload)`.
  Другой адаптер должен возвращать `Candidates`; проверка источников и объединение
  не зависят от OpenAI. Для checkpoint адаптер также объявляет `prompt_version`
  и `prompt_sha256`. Production-интерфейс использует только настоящий OpenAI-адаптер.
- Разбиение следует наблюдаемым разделам, пунктам и заголовкам. В основном блоке
  до 6 000 символов и 100 фрагментов; помещающийся пункт сохраняется целиком.
  Длинные пункты/фрагменты делятся по словам с исходными ID и смещениями.
  Каждый символ входит ровно в один основной блок. Добавляются до 1 200 символов
  с каждой стороны и до 6 000 символов заголовков/начал родительских пунктов;
  ограничение контекста отмечается в `coverage.chunks[].context_limited`.
  По умолчанию максимум 200 блоков; превышение вызывает ошибку до вызова API.
  Это ограничения символов, не обещание совместимости с контекстом любой модели.
- Из каждого блока извлекаются кандидаты процедур и действий, исполнитель,
  входы, результаты, условия и зависимости с доказательствами. Неизвестные
  сведения остаются `null` или `[]`. Определения и перечни не должны превращаться
  в действия; это правило инструкции модели, а не доказанная семантическая гарантия.
- Для цитат проверяются существование ID и точное совпадение **в переданном тексте**.
  Возвращаются все подходящие диапазоны символов, исходный пункт, способ привязки
  и физическая страница PDF. HTML/DOCX/TXT не получают выдуманных страниц.
  Ложное основное доказательство отклоняет действие; неподтверждённое дополнительное
  поле удаляется с причиной в отчёте. Номера пунктов модель не генерирует.
- Процедуры объединяются по подтверждённому исходному пункту/заголовку/фрагменту.
  Точные нормализованные повторы действий с общим местом доказательства сливаются;
  разные описания или условия сохраняются. Перефразированные дубли и ошибочная
  группировка процедур возможны и требуют ручной проверки.

**Совпадение цитаты доказывает расположение, но не смысл вывода.** Все действия
имеют `requires_review: true`, `validation: "exact_quote_match_only"`.
Покрытие всех символов не гарантирует полноты извлечения процессов моделью.
Дальние зависимости между разделами могут не попасть в ограниченный контекст;
автоматическая проверка юридической корректности не выполняется.

В JSON сохраняются источник и его хеши, модель/провайдер, время анализа, версия
инструкции, процедуры, действия, цитаты, причины отклонений и покрытие блоков.
Пустой список содержит объяснение модели по блокам; отклонение всех кандидатов
явно отличается от утверждения модели об отсутствии действий.

Для настоящего запуска из командной строки ключ должен быть внедрён в окружение:

```bash
python -m scripts.extract_processes examples/rosimushchestvo_261/source.txt \
  --output work/261.processes.json --check-261
python -m scripts.extract_processes tests/fixtures/law_59_article8_excerpt.txt \
  --output work/59.processes.json
```

`--check-261` только добавляет отчёт о найденных якорях 3.2–3.8 **после** анализа;
он не влияет на запросы или алгоритм. При необходимости уменьшите `--core-chars`.
CLI читает секрет из окружения, UI дополнительно поддерживает Streamlit Secrets.
Второй файл — явно обозначенный отрывок другого НПА, не полный закон.

Отчёт о текущих проверках и ограничениях реального запуска:
[docs/process-extraction-quality.md](docs/process-extraction-quality.md).
Автоматические тесты LLM используют mock-ответы и не подтверждают качество настоящей модели.
AI-инициативы, сценарная экономика и приоритизация описаны ниже;
реальные финансовые показатели ведомства из НПА не выводятся.

## Карта процессов и готовый анализ

Для уже выполненного анализа **не нажимайте «Извлечь процессы» повторно**:

1. Загрузите тот же исходный НПА. Для приложенного результата приказа № 261
   подходит `examples/rosimushchestvo_261/source.txt` редакции 30.05.2023.
2. Раскройте **«Технические данные»**, выберите свой
   `processes.json` и нажмите **«Импортировать результат»**. Проверяются схема,
   уникальность ID, хеши файла/текста, реквизиты и все цитаты с координатами.
   Значения `validation` и `requires_review` не освобождают импорт от проверки.
3. Если карта уже есть, в том же разделе загрузите `normalized_processes.json`
   и нажмите **«Восстановить карту»** — без API. Если сохранён только исходный анализ,
   нажмите **«Продолжить анализ»** на основном экране: выполнится только нормализация.
4. Основной экран показывает краткий список процессов и кнопку формирования отчёта.
   Подробности по выбранному процессу и действию доступны через
   **«Технические данные» → «Показать карту и доказательства»**. Здесь же находятся
   исходный текст, ID, хеши, отклонения, учёт кандидатов, метрики и checkpoint.
5. Скачайте неизменённый `processes.json`, отдельный `normalized_processes.json`
   и читаемый отчёт Markdown. После перезагрузки снова загрузите НПА и исходный
   анализ, затем JSON карты → **«Восстановить карту»** в техническом разделе.
   Ключ API для восстановления не нужен.

`checkpoint.json`, `processes.json` и `normalized_processes.json` — три разных
формата. Первый содержит промежуточные ответы извлечения, второй — завершённый
исходный анализ, третий — проверенный план нормализации и карту. Импорт не меняет
исходные байты. В памяти сессии карты хранятся отдельно по ключу совместимости;
**долговременная копия — скачанные JSON и сохранённый НПА**, не временный диск Cloud.

Нормализация возвращает короткие названия и связи исходных ID. Цитаты, координаты
и подробности берёт Python из заново проверенного источника. Обобщения не входят
в число операций. Участник и явно предусмотренный НПА способ выполнения —
независимые признаки; отсутствие автоматизации не означает ручной труд.
Различающиеся исполнители, каналы, сроки и условия могут блокировать объединение.
Неизвестные ссылки отклоняют план; непокрытые или спорно объединённые кандидаты
сохраняются в **«Требует проверки»**, карта помечается неполной.

Ключ карты учитывает исходный анализ, документ/структуру, модель/провайдера,
версию и хеш отдельного промпта, схему и настройки. При восстановлении карта
пересобирается из плана и доказательств; несовместимый/изменённый файл отклоняется.
Обычная навигация, скачивание и восстановление не создают API-запросов. Повторная
генерация доступна явно в технических данных или при неполной карте.

В этой версии используется **один общий ограниченный запрос**: до 400 000 байт
входа с инструкцией/схемой, до 400 кандидатов и 32 000 токенов ответа, таймаут
300 секунд, без автоматических повторов. Предварительная оценка ответа не заменяет
точную токенизацию. Вход сверх лимитов отклоняется до запроса, без усечения.
Разбиение нормализации на несколько запросов пока не реализовано. Ошибка второго
этапа сохраняет исходный анализ и не требует повторного извлечения НПА.

Версия промпта извлечения и схема checkpoint сохранены. Нормализация имеет
собственные `normalization-1.0` и схему `1.0`. Новых зависимостей нет.
Смысловая правильность объединений требует проверки; карта не восстанавливает
операции, пропущенные первым этапом. Подробные проверки, реальные ID и ограничения:
[docs/process-map-normalization.md](docs/process-map-normalization.md).

## AI-инициативы, эффект и отчёт

Основной сценарий: **загрузить НПА → «Извлечь процессы» → «Сформировать отчёт» → скачать результат**.
Извлечение и нормализация выполняются последовательно существующими функциями;
пользователь видит краткий перечень процессов, затем предложения ИИ с качественной
перспективностью и метриками эффекта. Основные загрузки — **«Скачать отчёт PDF»**
и **«Скачать все материалы ZIP»**. Архив содержит основной PDF, редактируемый DOCX, краткий Markdown, полный
`opportunities.json`, отдельные подробные материалы `opportunity-details.txt` и пояснение
с требованиями восстановления. Краткий отчёт рассчитан на объём до шести страниц;
длинное доказательное приложение в PDF/DOCX не включается. Если обязательное
содержание не помещается, полный PDF остаётся доступным с предупреждением о
превышении объёма: инициативы и условия не удаляются ради макета.

Импорт, подробная карта, исходные JSON, checkpoint и диагностика находятся в одном
закрытом разделе **«Технические данные»**. Новых аналитических этапов, обязательных
пользовательских действий или дополнительных LLM-запросов на инициативу нет.

### Проверка на уже сохранённых этапах

1. Загрузите прежний НПА. Для приложенной карты приказа № 261 подходит
   `examples/rosimushchestvo_261/source.txt` редакции 30.05.2023.
2. В **«Технических данных»** импортируйте соответствующий `processes.json`,
   затем восстановите `normalized_processes.json`. Извлечение и нормализация не запускаются.
3. Если отчёт уже есть, восстановите его `opportunities.json` через **«Восстановить отчёт»**
   в техническом разделе: API не вызывается. Только для новой генерации нажимайте
   **«Сформировать отчёт»** — это отдельный платный запрос с прежними защищёнными настройками.
4. Сразу сохраните **ZIP**. В новой сессии восстановите те же входные файлы и
   полноценный `opportunities.json` из архива через **«Восстановить отчёт»**.
   Цитаты, эффект и перспективность проверяются заново без API.

Частичная реконструкция `kind=govai_reconstructed_reference_not_application_artifact`
не является полноценным отчётом или резервным планом. Её schema/kind не подменяются.
Основной контрольный материал этой итерации — настоящий производный отчёт **2.2**
с восьмью инициативами из предыдущей итерации. Его версия проверена по содержимому;
полное восстановление прошло без API. Оригинал 2.1 сохранён отдельно и не переименован
в новую схему. Пользовательские файлы в репозитории не публикуются; тестовые mock-планы
явно отделены от настоящего результата.

### Что означает перспективность

Числовых баллов и весов нет. Номера № 1…N обозначают предварительную очередь
проработки, одинаковую в JSON, интерфейсе, Markdown, PDF и DOCX. Категории: высокая, средняя, низкая перспективность
либо недостаточно оснований. Высокая требует конкретной добавочной пользы ИИ,
ограниченного пилота, понятного измерения и контроля рисков. Средняя означает полезный
механизм с ещё не выполненным предварительным условием. Неизвестные данные не означают
автоматически низкую перспективность; квот категорий нет.

Внутри категории сохраняется стабильный порядок, если нет явной обоснованной
редакционной очередности. Она учитывает границы и измеримость пилота, зависимости
и риски, сохраняется вместе с результатом и не использует скрытые баллы. Исходные
ID инициатив не меняются; номера не доказывают объективное превосходство.

Один `management_view` используется сайтом, PDF, DOCX и Markdown: рекомендация,
ожидаемая польза, краткий перечень всех инициатив, первые обоснованные пилоты,
сценарный эффект и условия проверки. В существующем запросе модель возвращает
`presentation` с коротким названием, пользой, главным условием, описанием работы
и основанием выбора, а также общий `executive_summary`. Дополнительного запроса
на редактуру нет. Резюме не используется как рекомендация, если локальная проверка
отклонила предложение или выявила противоречие его перспективности.

Полные цитаты, цепочки источников, протоколы и диагностика доступны в отдельном
текстовом приложении ZIP и JSON. Краткое представление не меняет исходную аналитику.
Старые результаты без новых кратких полей используют совместимое представление;
им не приписывается новая редакция модели.

Проверяются объяснение `why_ai`, обычная альтернатива, границы/критерий пилота,
человеческая проверка и риски. Неполное или противоречивое обоснование сохраняется
с недостатком оснований, а не с необоснованной высокой категорией. Это структурная
проверка, не доказательство смысловой истинности ответа модели. Перспективность —
**не окупаемость и не готовность к промышленному внедрению**.

Резюме называет конкретных кандидатов для первой проверки, когда есть основания;
business cases объясняют проблему, пользу GenAI, альтернативу без него и критерий
успеха. Источники помещены в приложение и полный JSON. Технические фрагменты
заменяются деловыми формулировками без удаления остального смысла ограничения.

### Метрики, участники и сценарии

Поддержаны четыре категории: трудозатраты, деньги, время прохождения конкретного
этапа и качество. Выбирается основная метрика, при необходимости — дополнительная
для проверки. Расчёты выполняет Python с `Decimal`; источник числа — документ,
пользователь, сценарное допущение или неизвестно. Неизвестные значения не равны нулю,
отрицательный эффект сохраняется. Универсальных денежных подстановок нет.

- Труд ведомства, МФЦ/другой организации и заявителя обозначается отдельно.
  Неизвестный или смешанный участник не становится сотрудником ведомства: числовая
  оценка труда ждёт уточнения границ, качественная гипотеза остаётся.
- Для рабочих минут нужны индивидуальные объяснения работы до, действий модели,
  оставшейся проверки человеком и различий трёх сценариев. Пустого `note` недостаточно.
- Часы на заданную выборку не требуют зарплаты или годовой нагрузки. Дополнительно
  Python показывает условный эквивалент на **1 000 случаев**, не выдавая его за
  фактический объём. Без `case_count` основной результат часов остаётся неизвестным.
- Для уже подходящих случаев применимость не умножается повторно. Для всех обращений
  она нужна явно: неизвестная доля не превращается в 100%.
- Для качества требуются расчёт показателя, экспертный эталон, критерий успеха и
  недопустимые ошибки. Без наблюдений нет вымышленного процента улучшения.
- Длительность этапа не равна рабочим минутам или сроку всей услуги. Денежный
  эквивалент мощности не является доказанным сокращением бюджетных расходов.

Учебная арифметика: **1 000 × (20 − 12) / 60 = 133,33 человеко-часа**.
Это сценарная единица сравнения, не показатель Росимущества; время после включает
проверку и исправления. Качественный пилот может проверять долю пропущенных
существенных расхождений на экспертно размеченных материалах без обещанного процента
улучшения. Подробные формулы и примеры — в [методике](docs/ai-opportunities.md).

### Локальные ошибки, сохранение и ограничения

Нарушение ID/доказательств одной инициативы отклоняет именно её с причиной; другие
подтверждённые предложения сохраняются. Повреждённая карта, другой документ или
неразрешимая целостность плана прекращают сборку. Ошибка необязательного числового
допущения по возможности оставляет гипотезу и план измерения без прогноза.
Проверки цитат, уже предусмотренной автоматизации, человеческого утверждения и
двойного учёта сохранены. Неполная карта не выдаётся за подтверждённую.

Структурированный план сохраняется **в сессии до сборки**. После локальной ошибки
доступны **«Повторить сборку без API»** и валидированная резервная копия
`opportunities-plan.json` с отдельным `kind=govai_opportunity_plan`. Восстановление
заново сверяет её с документом, картой, схемой и настройками. План — не готовый отчёт;
первично невалидный ответ не создаёт обещания восстановления.

Готовый результат и активный запуск защищены от повторного клика. Просмотр,
перерисовка, скачивание и импорт не вызывают модель. PDF/DOCX/Markdown и ZIP используют
заранее подготовленные байты одного результата. Файлы и ошибки подготовки кешируются
по хешу артефакта и версии экспорта, поэтому навигация не повторяет сборку. Сбой одного
формата не скрывает остальные: доступны исправные файлы и полный JSON; неполный архив
явно обозначен и перечисляет отсутствующие файлы. **Сессия и media-файлы Streamlit не являются постоянным
хранилищем:** без скачанного файла после потери сессии восстановление не гарантируется.
Для гарантии понадобится отдельно согласованное приватное постоянное хранение;
новой инфраструктуры в этой итерации нет.

Лимиты: **400 000 байт** входа с промптом/схемой, **800 записей**, **20 000 токенов**
ответа, **300 секунд**, без автоматических повторов. Превышение входа обнаруживается
до API, без усечения. На сохранённой карте № 261 новый полный запрос занимает
**395 719 байт**: запас до лимита — только **4 281 байт**. Более объёмная карта
может быть отклонена до запроса. Размер в байтах не является точным числом токенов.

Новая генерация возвращает отчёт **2.3** с промптом **opportunities-2.2** и
`OpportunityGenerationPlan`; расчёт **effect-2.1** и рубрика **prospect-1.1** не изменены.
Полные результаты **2.1 и 2.2** читаются по их прежним строгим контрактам. Версию
нельзя подменить вручную. `rebuild_opportunities` использует сохранённый план,
явные предпосылки и редакционные основания без API, сохраняя происхождение.
Извлечение, нормализация и checkpoint остаются совместимыми.

Новых зависимостей и production-модулей в этой итерации нет. PDF использует уже
установленный `reportlab==5.1.0` и включённые шрифты Liberation Sans с кириллицей;
LibreOffice или внешний конвертер в Streamlit Cloud не нужен. DOCX использует
тот же шрифт с согласованной заменой Arial.

Настоящий сохранённый результат № 261 восстановлен без API: **8 инициатив,
6 отклонений, 45 проверенных цитат**, карта остаётся неполной. Новые PDF и DOCX
содержат по **5 страниц** в проверенном рендере. Подготовка комплекта файлов
заняла около **0,25 с** в среде разработки; это только локальный экспорт, а не
анализ НПА или обещание скорости в Cloud. Навигация использует готовые байты.
Реальных новых OpenAI-вызовов нет; качество нового промпта пока не подтверждено
настоящим ответом. CI использует Python 3.12, `requirements-dev.txt`, `pytest`
и `compileall`, без секретов и API.

### Проверка опубликованного приложения владельцем

Публичный адрес: [GovAI в Streamlit Cloud](https://govai-opportunity-engine-st8q5tcewhhhg9e2vfpxyd.streamlit.app/).
Из среды Codex доступ к этому адресу пока ограничен сетевым прокси. Это **не
доказательство недоступности самого сайта**; опубликованные commit, настройки и
полный путь посетителя ещё нужно подтвердить снаружи.

1. В существующем Streamlit Cloud app проверьте репозиторий, ветку
   `codex/streamlit-document-upload` и запуск `app.py`; дождитесь обновления
   проверенного коммита. Не создавайте новое размещение.
2. В защищённых настройках владельца проверьте наличие `OPENAI_API_KEY` и
   согласованной `OPENAI_MODEL`. Ключ не отправляйте в чат и не публикуйте.
   После загрузки документа «Технические данные» показывают фактический commit,
   ветку, модель и заполненность настроек без раскрытия ключа. Это не тест API.
3. Откройте публичный URL в чистой сессии. Загрузите новый публичный НПА,
   сверьте название/редакцию, выполните «Извлечь процессы» и «Сформировать отчёт».
   Этот проход платный; ограничьте проверку одним согласованным документом,
   не повторяйте запрос автоматически после ошибки.
4. Скачайте PDF и ZIP с основного экрана. Проверьте кириллицу, все страницы,
   текущий документ, состав архива и полный JSON. Замените документ и убедитесь,
   что прежний отчёт исчез. Просмотр и скачивание не должны увеличивать число запросов.
5. Сохраните результаты и времена этапов. Отдельно пройдите путь на физическом
   телефоне и в сети проверяющего с VPN и без VPN: эмуляция ширины не заменяет эти проверки.

## Известные ограничения

- Правила выделения структуры эвристические. Явный маркер не доказывает, что это
  юридический пункт: это может быть элемент списка или поле формы. Ненумерованные
  и перенесённые заголовки распознаются частично; `heading_candidate` требует проверки.
- Продолжение пункта относится к последнему явному маркеру до обнаруженной границы.
  После неоднозначного списка принадлежность не назначается. Сложные сноски,
  вложенные списки, таблицы и нестандартная вёрстка могут потребовать ручной разметки.
- PDF: номер — позиция страницы в файле, а не напечатанный номер. Пустые страницы
  не исчезают. Повторяющиеся строки на краях сохраняются как `layout_candidate`;
  иногда это может быть содержательный текст. OCR и восстановление колонок отсутствуют.
- DOCX не имеет надёжной физической пагинации без отдельного рендеринга.
  Автоматическая нумерация Word не вычисляется: её отсутствующие в тексте номера
  не выдумываются. Колонтитулы, текстовые поля, отслеживаемые правки и изображения
  не входят в поддерживаемый текстовый слой.
- Сохранность фрагментов проверяется относительно извлечённого текста. Она
  не доказывает, что PDF/DOCX-библиотека извлекла все видимые элементы оригинала.
  Для юридически значимых выводов нужны сверка с оригиналом и проверка редакции.

## Структура

```text
app.py                     # Интерфейс Streamlit
govai/extraction.py         # Извлечение и проверка документов
govai/structure.py          # Структура, реквизиты и точные ссылки на текст
govai/url_input.py          # Безопасная загрузка HTTPS и извлечение HTML
govai/processes.py          # Блоки, контракт LLM, цитаты, объединение кандидатов
govai/checkpoints.py        # Совместимость, JSON и повторное использование ответов блоков
govai/llm.py                # OpenAI Responses + Structured Outputs
govai/analysis_io.py        # Проверка импортированного завершённого анализа
govai/normalization.py      # План группировки, учёт ID, проверка и экспорт карты
govai/process_ui.py         # Извлечение, импорт processes.json и checkpoint
govai/map_ui.py             # Общий renderer карты, запуск и восстановление
govai/opportunities.py      # План AI-инициатив, ссылки, совместимость и восстановление
govai/economics.py          # Чистые расчёты сценариев и контроль пересечений
govai/opportunity_report.py # Качественная перспективность и Markdown-отчёт
govai/opportunity_ui.py     # Основной экран отчёта, загрузки и техническое восстановление
govai/report_export.py      # PDF/DOCX и ZIP из общего управленческого представления
govai/document_ui.py        # Реквизиты и отдельный технический просмотр
.streamlit/config.toml     # Лимит загрузки и отключение телеметрии
requirements.txt           # Зависимости приложения
requirements-dev.txt       # Зависимости для тестов
tests/                     # Тесты извлечения и интерфейса
examples/rosimushchestvo_261/ # Реальный НПА, источники и пример результата
scripts/build_npa_example.py # Воспроизведение примера без сети
scripts/extract_processes.py # Настоящий вызов API и отчёт по якорям приказа 261
```

Файлы `.env`, `.streamlit/secrets.toml`, виртуальное окружение и временные
файлы исключены через `.gitignore`. Секреты требуются только для LLM-извлечения,
генерации карты и AI-инициатив.
